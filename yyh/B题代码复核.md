## 第四问改了什么

| 复现问题 | 修订与验收 |
|---|---|
| V5 故障仅涉及已启动的 T1。原“跳过”策略却取消健康车辆的转向，导致 T3 从 10.387101 s 推迟到 15.777589 s。 | 跳过需要故障车的待办任务，其余车辆保留已经走过的行程、转向进度和等待状态。本例修订后的 T2、T3 与原计划同时启动。55 条跳过策略记录的个别启动时刻修正，其中 3 条改变了最终成绩。 |
| 原日志中 768 条单车观测启动缺少云台姿态，888 条出发记录的路线不能按 JSON 读取。取消旧任务后的回正时间也无法从日志还原。 | 补记取消、从当前姿态复位及复位结束，统一路线序列化。发布表逐行核对出发姿态和路线净空，逐项核对两车到站、完成指向、方位角、仰角、站对及共同启动时刻。 |
| 任一待办任务没有可行候选时，旧搜索可能直接抛出异常。题目要求此时结算窗口内已成功启动的告警。 | 候选耗尽时，按能实际执行的部分计分。回归用例覆盖候选为空、启动恰在 60 s 和晚于 60 s。 |
| 原第四问读取计划时只看可行标记。同一输入在 LF、CRLF 两种检出方式下会得到不同摘要。 | 先按第二问清单的 UTF-8、LF 口径核对计划，再开始回放。改动一个字节的有效内容会触发错误。结果文件另按实际发布字节校验。[冻结清单](../results/question2/manifest.json) · [第四问清单](../results/question4/manifest.json) |

两份既有审稿共 8 项，原稿中的处理记录已经存在。本轮用其测试用例复验，并在[意见索引](../修改意见/README.md)登记截止版本。获知故障前继续执行手头指令、恢复时健康搭档仍在等候、故障车保持退出姿态，均可在同一场景的快照与日志中对照。

## 两项结论的边界

- **第二问（2）的连续站位。** 保持原车对、任务次序和其余站点，只把 V3 对 T1、T3 的共用站改为 (16.76, 88.68) m，`evaluate_schedule` 返回可行，最晚启动为 10.385224443 s。这比冻结值早约 1.877 ms。第四问沿用团队用于配对比较的冻结计划。连续全域最优性仍待证明。
- **第四问的胜负。** 在仅 V5 故障时，三种策略均启动 3/3。保留计划与确认后跳过均为 10.387101 s。实时重调度因取消原有指向、重新分配，最晚启动为 15.777589 s。纯断联时，团队采用的“0 s 已完整下发原计划”假设使两种主策略持平。只有故障身份有题给概率，其他样本的胜负计数限于本次场景设计。[场景与实验说明](../src/QUESTION4.md)
