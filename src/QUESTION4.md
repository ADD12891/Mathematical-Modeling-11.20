# 第四问 · 扰动实验与实时重调度

## 运行

从仓库根目录执行：

```powershell
python -m src.disturbance
python -m src.disturbance --list
python -m src.disturbance --scenario new-N1-failure-V1-outage-rec-30 --output-dir q4-debug
python -m unittest -v src.test_disturbance src.test_disturbance_reporting src.test_question4_outputs
```

程序用第二问清单核对原计划，再将全量结果写入 `results/question4/`。只给 `--scenario` 时，输出放在该目录的 `debug/<场景编号>/`。单场景表头与全量文件兼容，只有五种故障身份齐全才会生成等权汇总行。

## 实验设计

扰动时刻固定为 5 s。新增告警设置为 12 个确定性因子组合：方位角取 0°、90°、180°、270°，水平距离取 30、40、50 m，高度均为 50 m。单车故障枚举五辆车。主实验将通信恢复时刻设为 10、20、30 s，即中断时长分别为 5、15、25 s。另设时长敏感性组，取 5、17.5、30 s，对应恢复时刻 10、22.5、35 s，并在结果中单独标记。

主实验有 311 个场景，时长敏感性组另有 234 个场景标签，两组合计 545 个标签。两组在恢复时刻 10 s 处存在相同物理条件，应分组报告，不能把标签数当作互斥随机样本数。12 个新增告警对方位和距离做完整因子覆盖。它们是用于比较算法响应的确定性代表点，不是从连续参数范围随机抽样，也不代表新增告警的概率分布。原题只给出五种故障身份等概率，未指定方位、距离或恢复时刻的概率分布。

| 策略 | 行为定义 |
|---|---|
| `retain_original` | 回放冻结原计划；新增告警不进入原分配。故障导致双车任务不能执行时，相关健康车按原计划等待。 |
| `skip_failed_task` | 故障敏感性对照。跳过需要故障车的任务，剩余任务沿用原分配、站点和顺序。 |
| `realtime_reschedule` | 在当前车辆状态和允许的信息时点上，重新分配未锁定任务，并联合选择车辆任务顺序与站点。 |
| `triggered_reschedule` | 确认扰动信息后，检查新增任务及故障车未启动的任务。集合为空时继续原指令，否则调用与原实时策略相同的重调度搜索。 |
| `local_repair` | 在相同触发条件下试算保留不同任务组合的排程。健康车辆继续执行选中任务的原指令，其余待办任务沿用同一个搜索器改派。 |

原计划假定在 0 s 已完整下发。因此仅通信中断而没有新任务或故障时，车辆继续执行手头已收到的计划，保留原计划与重调度结果相同是预期现象。通信中断与新增告警、故障组合时，重调度等待恢复后再使用新信息。

同刻规则为先推进到 5 s，再锁定实际启动时刻严格早于 5 s 的观测，然后处理扰动，最后重新判断恰在 5 s 启动的任务。得分窗口为闭区间 `[0, 60]`。窗口内启动任务数决定完成率；任务不全时 `t_last` 记为 60 s。

## 判断一次重排是否必要

英文原题第 5 页允许改派已出发但尚未开始观测的车辆。沿用第二问已下发的计划，令 A 为本次新增告警，F 为故障车原定的任务集，L 为故障发生前该车已经共同启动的任务。无新告警或无故障时相应集合取空。决策时计算 **A ∪ (F − L)**。集合为空时保留健康车辆的指令，否则重排所有仍可改派的任务。由故障间接阻塞的后续任务在重排时一并处理。

在题给的单次扰动和标称行驶时间下，如果故障车的所有任务都已启动且没有新增告警，健康车辆余下的行驶、转向和共同启动仍可按原计划执行。断联时等恢复通信后才作决定，判断所用的是原任务队列和故障前的启动记录。策略的车辆事件日志在决策行的 `decision` 列记录动作，`reason` 列以 JSON 数组记录触发任务。

在 311 个主实验中，有条件策略与原实时策略相比，2 个同完成率提前、309 个持平；相较保留原计划，304 个增加启动数、7 个同完成率持平。时长敏感性组相应为 1/233 个与原实时策略相比提前/持平，228 个增加启动数、6 个同完成率持平。该策略在两例已知退步的 V5 场景中恢复至冻结计划的 10.387101 s。场景计数仅反映设计样本，不是概率加权效果。[全部配对成绩](../results/integration/triggered_comparison.csv)

该规则只决定是否启动现有搜索。即使原计划还可执行，其他排程也可能更快；触发搜索后仍受候选集和搜索宽度限制。样本成绩支持减少特定无效改派的结论，全局最优性尚无证明。

## 当前结果

### 哪些指令值得保留

对于每项尚未启动的原任务，先检查故障是否直接或沿车辆队列阻塞它。保留一个任务时，其两个搭档各自排在它之前的未启动任务都必须保留。满足这条规则的组合可以逐一枚举。每个组合中，选中任务保留原车对、站点和时刻；每辆车完成自己最后一个保留任务的复位后，才能从该站点出发。其余任务交给原来的搜索器。算法在允许下达指令时，用当时已知的扰动和标称行驶、转向时间试算各个组合。

方案先按 60 s 窗口内启动数、再按最晚启动时刻排序。两项均相同时，优先选择显式取消指令少的方案，其次选择保留任务多的方案。空集合对应上一版触发后的重排，所以在相同求解器、相同标称回放条件下，新版至少有一个与上一版等分的候选。保留组合最多为 2 的 m 次方，m 为可保留的未启动任务数；每个有效组合需要试算一次剩余任务，计算开销随任务数增长。候选站位和车对搜索的限制仍然适用。

局部改派还可以保留单辆健康车已完成的指向。需同时满足三个条件：决策前的实际事件已记录转向完成，此后车辆持续等待，后续安排仍是同目标、同站点。共同观测开始后，两车照常完成 5 s 观测并分别复位。每次决策同时试算关闭这项功能的排程，用同一批输入检验收益。

311 个主实验中，两版局部改派均全部启动。相对只保留整项任务的版本，单车指向复用使 95 个场景提前、216 个持平。234 个时长敏感性标签中，96 个提前、138 个持平。该消融只说明所选确定性样本中的比较结果。事件日志中，`pointing_retained` 标记实际复用的车辆和任务，决策记录的 `without_ready_reuse` 保存同轮关闭复用时的结果。[逐场景比较](../results/integration/local_repair_comparison.csv)

### 早期策略对照

实时重调度在本次设计的全部场景中都让每项告警在 60 s 内启动。按题定顺序与保留原计划配对比较，311 个主实验中有 304 个增加启动数、5 个同完成率持平、2 个同完成率变慢。234 个时长敏感性标签中分别为 228、5、1。下表每格依次给出启动数/告警数和最晚启动时刻（s）。这些计数不是连续方位、距离或恢复时间上的概率结论。[逐场景成绩](../results/question4/scenario_scores.csv)

| 场景 | 保留原计划 | 确认后跳过 | 实时重调度 |
|---|---|---|---|
| 仅新增 N1 | 3/4，60 | — | 4/4，18.492339 |
| 仅 V5 故障 | 3/3，10.387101 | 3/3，10.387101 | 3/3，15.777589 |
| 仅断联至 30 s | 3/3，10.387101 | — | 3/3，10.387101 |
| N1、V1 故障、断联至 30 s | 2/4，60 | 2/4，60 | 4/4，39.582129 |

V5 唯一的任务 T1 已在 2.332055 s 启动。保留原计划时，其余车辆可照常完成 T2、T3。实时策略仍取消未启动任务，车辆需要复位、重新指向，T3 因而晚了 5.390488 s。纯断联时，全计划已经下发，各车按原时刻执行。

最后一行可用上面的单场景命令复查。T3 在断联期间于 10.387101 s 启动。30 s 恢复后，V3、V5 接手原来缺少 V1 的 T2，在 35.075142 s 启动。V2、V4 在 39.582129 s 启动新增的 N1。

## 输出文件

| 文件 | 内容 |
|---|---|
| `scenarios.json` | 每个场景的扰动参数、故障车、恢复时刻、中断时长和计分分母。 |
| `scenario_scores.csv` | 场景与策略级成功数、完成率、最晚启动时刻及完整告警启动时刻映射；未启动告警显式记为 `null`。 |
| `event_log.csv` | 配对策略事件记录，包含车辆、任务、阶段、时间和状态信息。扰动前已执行事件保留，故障车在 5 s 退出后不再有动作记录。 |
| `aggregate_scores.csv` | 按扰动集合、策略和中断口径汇总的均值、最好值和最差值。 |
| `snapshots.csv` | 5 s 扰动前、故障刚发生后及通信恢复收取新指令前，五车实际位置、姿态、阶段与任务。 |
| `fault_groups.csv` | 固定新增告警、恢复时刻和策略，五种故障各占 1/5 的平均成绩、最好及最差成绩和对应故障车辆。 |
| `manifest.json` | 原计划和源码按 UTF-8 文本统一换行后计算 SHA-256，结果按实际发布字节校验。 |

重调度枚举待办任务顺序。对每个任务，每车最多考虑两个近邻站位，按可通路线、同步启动时间等筛选车对与站对，再保留排名前两种组合继续搜索。所得成绩对应这项启发式，其他近邻组合、其他站位与连续场地均可能给出更好的方案。
